# 学习任务输出模板

本文件是 SKILL.md 引用的模板：定义 Life2English 生成学习任务时的**标准输出结构**。
交互式 CLI 与 `skill_api.py` 的 `task` / `run` 动作都按此结构组织内容。

## 渲染模板（交互式终端）

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  学习任务 · {scene_name}（难度：{difficulty}）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【学习目标】
  {goal}

【实用表达】（{n} 条）
  1. {expression.en}
     {expression.zh}
     · {expression.note}
  ...

【互动任务】
  {interactive_task}

【注意事项】
  · {note}
  ...
```

## 字段规范

| 字段 | 必填 | 约束 |
|---|---|---|
| `scene_name` | 是 | 场景中文名，与模板库一致 |
| `difficulty` | 否 | 入门 / 入门-进阶 / 进阶 |
| `goal` | 是 | 一句话学习目标，说明学完能做什么 |
| `expressions` | 是 | **5 条**实用表达；每条含 `en`（英文例句）、`zh`（中文释义）、`note`（用法提示） |
| `interactive_task` | 是 | 明确的互动任务，说明系统扮演什么角色、用户要做什么 |
| `notes` | 否 | 1–3 条注意事项 / 易错点 |

## 内容要求

- 表达**实用、自然**，适合大学生日常交流；避免书面化、教材腔；
- 中文释义准确，用法提示要能解释「为什么这样说」，而不只是翻译；
- 互动任务必须与表达对应，让用户有机会用上学到的句式；
- 不得虚构场景能力：只输出模板库中确实存在的内容。

## JSON 表达（协议输出）

```json
{
  "task": {
    "scene_id": "coffee_ordering",
    "scene_name": "咖啡店点单",
    "difficulty": "入门",
    "goal": "学会在咖啡店用英语完成一次完整点单：打招呼、点单、说明杯型（堂食/外带）、结账致谢。",
    "expressions": [
      {"en": "Hi, could I get a medium latte, please?", "zh": "你好，请给我一杯中杯拿铁。", "note": "点单最常用句式：Could I get ..., please?"}
    ],
    "interactive_task": "接下来我是咖啡店店员，你是顾客。请用上面的表达完成一次点单，我至少会问 2 个问题。",
    "notes": ["Could I get ... 比 I want ... 更礼貌，点单场景优先使用"]
  }
}
```

## 情境互动 / 反馈 / 迁移 / 总结的对应模板

- **情境互动**：`{role_zh}：{opening}` → 每轮 `{role_zh}：{prompt}` + `（提示：{hint}）` → `{role_zh}：{closing}`
- **表达反馈**：逐条 `· [{类别}] {quote} → {fix}` + `—— {reason}`；结尾固定输出**总体结论**与**局限说明**
- **迁移练习**：`【新场景】{scenario}` + 任务提示 + `（示例：{example}）` + 复用情况说明
- **学习总结**：按 `场景与目标 / 核心表达 / 实际完成情况 / 需要注意 / 下一步练习建议` 五个小节输出，
  内容全部来自本次会话实际记录，未完成的环节如实标注。
