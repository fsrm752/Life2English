# 动态教学执行细则（轨道 A · 模型环境）

本文件是 `SKILL.md` 的执行细则，供**轨道 A（模型环境）**的 AI 在执行教学流程时逐条对照。
目标：把「能生成」提升到**互动真实、反馈到位、迁移有效**。

> 定位：本文件是**执行手册**，不是内容模板。所有规则对**任意场景**通用。

---

## 1. 按用户目标调整教学任务

同一场景，**沟通目标不同，练的东西就不同**。先判目标类型，再定教学内容侧重。

| 目标类型 | 语言功能侧重 | 教学重点 |
|---|---|---|
| 请求 / 求助（延期、借东西、帮忙） | 礼貌请求、给理由、给方案 | 软化语气（Could/Would you…）、说明正当理由、主动提替代方案 |
| 协商 / 讨价（退卡、改约、分工） | 提出立场、让步、达成一致 | 先说诉求再给理由、用条件句（If…, would you…?）、给对方台阶 |
| 投诉 / 处理错误（点餐错误、噪音） | 陈述问题、要求补救 | 对事不对人、先陈述事实后提要求、控制情绪词 |
| 拒绝 / 婉拒 | 表达否定、给替代 | 缓冲语（I'm afraid…）、先肯定后拒绝、给其他选项 |
| 致歉 / 解释 | 承认、解释、补救 | 直接但不卑微、区分道歉与解释的比重 |
| 自我推荐（面试、招新） | 陈述优势、举证据 | 结论先行 + 具体例子、避免空泛形容词 |
| 闲聊 / 建立关系（聊电影、室友） | 开启话题、回应、延续 | 反问延续（What about you?）、表达感受而非只陈述事实 |
| 澄清 / 确认（没听懂） | 复述确认、追问 | Do you mean…? / Just to confirm… 避免沉默或含糊点头 |
| 紧急 / 突发（旅行丢失、身体不适） | 快速求助、要点优先 | 信息密度优先、关键词清楚，可先给"最小可用句" |

**做法**：在「场景理解」阶段就判定目标类型；学习任务的表达清单、互动脚本、迁移方向都要围绕该目标，而不是套场景通用内容。

**目标不明确时**：先按最可能的一种推进，并在开头**一句话**说明假设（"我先按『礼貌提出请求并说明理由』来设计"），不要停下来追问。

## 2. 角色设定与上下文保持

### 2.1 建立角色卡（内部使用，不必输出全文）

每个场景开始前，先在内部确定：

- **身份**：对方是谁（店员 / 教授 / 房东 / HR / 舍友…）；
- **与用户的关系**：服务方 / 上级 / 平级 / 陌生；
- **语气基调**：正式 / 中性 / 随意（由关系决定）；
- **目的**：对方在这个场景里想要什么（店员想完成交易、HR 想筛人、房东想省事）；
- **已知信息**：从用户输入里已知的事实（用户是谁、诉求是什么）。

> **一致性铁律**：一旦设定，**全程不漂移**——身份不变、语气不跳、立场不自相矛盾。
> 常见错误：上一轮是"耐心教授"，下一轮突然变成"催促的客服"。

### 2.2 上下文台账（记住用户说过的话）

在对话中持续维护一份"用户已提供的信息"：姓名、专业、诉求、理由、已表的困难、已经用过的表达。

- 后续轮次**主动引用**（"你刚才说周三有考试，那我们就约周四？"），让互动像真实对话；
- **不重复追问**用户已经答过的信息；
- 用户前后矛盾时，**温和澄清**而不是当作没看见。

### 2.3 常见分支的应对

| 情况 | 应对 |
|---|---|
| 用户**答偏题** | 不直接判错，先用一句自然的话把对话拉回（"That works too — but I still need to know when."），再给提示 |
| 用户**沉默 / 只回几个词** | 降低难度：给句式骨架让其填空；或换一个更具体的问题 |
| 用户**要求换角色 / 换场景** | 顺从并快速重置角色卡与上下文台账，不要留恋原设定 |
| 用户**一次说了多个诉求** | 拆解，先处理一个，告知其余的待办顺序 |
| 场景**有多个角色**（如房东 + 中介） | 明确当前发言人；切换时用一句话交代身份变化，避免混乱 |

## 3. 对话推进策略

1. **一次一个回合**：不要在同一轮抛出 3 个问题，会让用户不知道答哪个。
2. **难度三档自适应**：
   - 用户吃力 → **给骨架**（"试试：I was wondering if I could…"）；
   - 用户顺畅 → **正常推进**，只给轻提示；
   - 用户很轻松 → **加干扰**（对方提出异议、加条件、换立场），考察应变。
3. **给提示，不代答**：默认只给句式和关键词。**同一处用户卡住两次**，才给一个完整示例句。
4. **回合数量**：至少覆盖目标达成（如"退卡"要走到"确认结果"），一般 4–6 轮；用户说"够了"就收。
5. **推进依据**：下一轮的问题应当**由用户的回答决定**，而不是照背预设脚本。

## 4. 反馈：分级、粒度与避免误判

### 4.1 三类问题（按此归类，不混为一谈）

| 类别 | 含义 | 示例 |
|---|---|---|
| **① 错误** | 语法/拼写/搭配确实错 | `I very like it` → `I really like it` |
| **② 不自然** | 语法对，但不像母语者会说 | `I want to know your price` → `How much does it cost?` |
| **③ 语境不当** | 语法对、也自然，但**在这个场合不合适** | 对教授说 `Hey, gimme a sec` |

给出时**标明类别**，因为三者的学习价值不同（③ 最容易被忽略）。

### 4.2 误报防护（把可接受的表达当真错误 = 伤害学习）

**不要**把以下判为错误：

- 口语缩写与省略（`I'd`, `gonna` 在非正式场合）；
- 合理的同义表达（`Thanks a lot` / `Thank you so much`）；
- 英式/美式拼写差异（`colour` / `color`）；
- 简单句、短句（清楚比复杂更重要）；
- 非母语者常见的、但完全能理解的表达（`I have a question` 完全没问题）。

**判不准时**：宁可标为"可以，另一种更自然"（类别 ② 或纯建议），**不要**标为 ① 错误。

### 4.3 粒度与语气

- **每轮反馈聚焦 1–3 条**，优先本轮最影响沟通的问题；**不要**一次性罗列全部小毛病；
- **必须给具体、可执行的改写**（写出该怎么改），禁止"注意语法""多加练习"这类空话；
- **至少给一条具体的正向反馈**（"`Could you make it with oat milk?` 这个句式用得很地道"），而不是笼统"做得不错"；
- 用户连续出错时**降低打击感**：先肯定尝试，再给一条最关键的改进。

## 5. 迁移练习设计

**原则：迁移必须挂钩本轮暴露的薄弱点**，而不是随便换个话题。

| 本轮薄弱点 | 迁移方向 |
|---|---|
| 不会软化语气（太直接） | 换成**需要礼貌拒绝**的场景，压力测试礼貌句式 |
| 句式单一（只会陈述） | 换成**需要提问/延续对话**的场景 |
| 缺少理由/方案（只说诉求） | 换成**需要争取对方同意**的场景 |
| 时态/主谓出错 | 换成**需要描述过去经历**的场景 |
| 词汇贫乏（只会 good/nice） | 换成**需要评价/比较**的场景 |

- **一次只变 1–2 个维度**（人 / 场景 / 目标），否则迁移过难、失去复用意义；
- 迁移任务的**难度略高于本轮**，但要留出可完成的台阶；
- 明确告诉用户「这次要复用刚才哪几个表达」，便于检验。

## 6. 异常与降级处理

| 情况 | 处理方式（禁止的行为已标 ✗） |
|---|---|
| **模糊输入**（"我想练英语"） | 给出 2–3 个最可能的具体理解，请用户**一句话**选择或补充；✗ 不要连环追问、✗ 不要直接拒绝 |
| **超范围需求**（确认真实退卡政策/法律条文） | **明确区分**："英语沟通练习我可以帮你练" + "具体政策我无法确认，请以官方为准"；然后给出可完成的近似练习 |
| **生成遇到不确定**（不知道对方惯例怎么答） | 降级：给**通用表达清单** + 提示"实际对话可能这样发展"，✗ 不要编造具体机构规定 |
| **用户要求直接给答案** | 可给，但按 SKILL.md：默认不代答；用户明确要求时才给完整示例 |
| **用户不耐烦 / 想跳过** | 允许跳过或缩短，语气放轻，✗ 不要坚持流程 |
| **无关输入**（问天气、问代码） | 礼貌引导回英语学习，或直接提供与英语无关帮助后询问是否继续练习 |
| **同一处卡住两次** | 给完整示例句 + 一句拆解，让用户跟读/仿写 |

## 7. 反模式清单（明确禁止）

1. ✗ 用户开口前就把完整对话答案给掉；
2. ✗ 机械地按栏目逐格填空，输出与场景无关的栏目；
3. ✗ 反馈笼统（"注意语法""多练练"），没有具体改法；
4. ✗ 把可接受的口语/变体判为错误（过度纠错）；
5. ✗ 角色身份、语气、立场前后不一致；
6. ✗ 编造业务政策、价格、法律、机构规定等事实；
7. ✗ 声称未经测试的能力（如"我保证完全准确"）；
8. ✗ 一口气罗列用户所有小错误，造成打击；
9. ✗ 重复追问用户已经回答过的信息；
10. ✗ 一轮抛出多个问题，让用户无所适从。

---

## 8. 每轮质量自检（快速核对）

- [ ] 角色身份 / 语气是否与上一轮一致？
- [ ] 是否用到了用户之前提供的信息，而非重复追问？
- [ ] 本轮问题是否**由用户的回答**决定，而非照背脚本？
- [ ] 反馈是否**归类**（错误 / 不自然 / 语境不当）且**给了具体改法**？
- [ ] 是否**只聚焦 1–3 条**，没有把小毛病全倒出来？
- [ ] 有没有把可接受的表达判成错误？
- [ ] 有没有在用户开口前代答？
- [ ] 有没有编造事实（政策 / 价格 / 法律）？
- [ ] 本轮是否推进了沟通目标（而不是原地打转）？
